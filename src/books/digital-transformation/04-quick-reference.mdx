## Definitions

| Term | In one line |
|---|---|
| **Digitisation** | Paper records become electronic. Gathering and storing |
| **Digitalisation** | Stored data is cleaned and made to flow between systems |
| **Digital enablement** | Equipping people and processes to act. The means |
| **Digital transformation** | The business measurably improves. The end |
| **Digital artefact** | A tool you own: ERP, dashboard, cloud account |
| **Output** | The thing you now have |
| **Outcome** | What now happens differently because of it |
| **Change vs transformation** | Any shift vs an intended, lasting, positive one |
| **Data hygiene / liquidity** | Is the data clean? / Does it move freely to where it's needed? |
| **Value** | Revenue minus cost: the surplus |
| **Top line / bottom line** | Revenue / profit |
| **Value chain** | One firm's primary and support activities |
| **Value system** | The connected chains of suppliers, partners and customers |
| **Adoption** | An attitude before use: is it easy, is it useful to me? |
| **Usage** | Observable behaviour after acceptance |
| **Override rate** | How often people reject the system's recommendation |
| **Psychological safety** | People share and help only when it can't be used against them |
| **Value re-creation** | Recovering value that has been lost |
| **Value co-creation** | Separate firms building value so all are better off |
| **Co-opetition** | Rivals co-operating in one defined area while competing elsewhere |
| **Data product** | A clean, standard, ready-to-use data set for a function |
| **Data governance** | Ownership, definitions, quality, access and sharing of data |

## Frameworks

| Framework | In one line |
|---|---|
| **The ladder** | Digitisation → digitalisation → enablement → transformation |
| **Noun and verb** | What we have vs what we do. Only verbs show improvement |
| **Porter's value chain** | Primary: inbound logistics, operations, outbound logistics, marketing and sales, service. Support: infrastructure, technology, people, procurement |
| **Two levers** | Push cost down (cost leader) or pull revenue up (differentiator) |
| **Uses of surplus** | Reinvest, distribute, or diversify |
| **Growth directions** | Related, unrelated, forward integration, backward integration |
| **ITOT / PT / BT / DT** | Technology lands in support / one process / the business model / directly on primary activities |
| **Security** | Cyber security (systems), data security (data), data privacy (the individual) |
| **Five building blocks** | Leadership, collaboration, data empowerment, value realisation, workforce |
| **Three qualities** | Data (the number), service (the people who fix it), system (the tool) |
| **IS Success Model** | Three qualities → use and satisfaction → net benefits |
| **Technology Acceptance Model** | Perceived ease of use + perceived usefulness → intention to use |
| **Readiness, five areas** | Leadership, organisation, data, decision intelligence, workforce |
| **Information systems triangle** | Transactions → pipelines → decision support or decision automation |
| **Data monetisation** | Improve internal work, wrap the offering, sell the information |
| **Scope, ways, means, ends** | Why and how far; which path; what it runs on; what shows up |
| **SERVQUAL (RATER)** | Reliability, assurance, tangibles, empathy, responsiveness |
| **Balanced Scorecard** | Learning and growth → internal process → customer → financial |
| **Need tree** | Outward opportunity (top line) or inward shortcoming (bottom line) |
| **Differentiation** | Product innovation or customer closeness |
| **Five ingredients** | Organisational capabilities, leadership, workforce, data governance, analytics |
| **Data architecture** | Grassroots, monolithic, or hybrid with a data-product layer |

## Easy to confuse

| If you see… | Remember… |
|---|---|
| "We migrated to the cloud" called transformation | A lower-rung output. Ask what improved |
| Enablement vs transformation | Means vs end |
| Dashboard usage of three hours a day | An output. Usage isn't benefit |
| "Access to data" as the outcome | The outcome is insight someone acts on |
| ITOT vs DT with the same technology | Internal users: ITOT. Customers served directly: DT |
| An automated internal task | Process transformation, not digital transformation |
| "The system is bad" | Which quality: data, service or system? |
| Adoption vs usage | Attitude before use vs behaviour after |
| High usage, flat results | Check satisfaction and the override rate |
| Ability vs attitude | Training vs change management |
| Collaboration vs co-creation | Inside one firm vs across separate firms |
| Co-opetition vs lobbying | Creating shared value vs pressuring a third party |
| Data governance vs data quality | Quality is one part of governance |
| Cyber security vs data security vs privacy | Systems vs data vs the individual |
| Technology ranked last among the ingredients | A hygiene factor: needed, never sufficient |

## Which case illustrates what

| Case | Use it for |
|---|---|
| **The logistics firm** | Data quality and service quality failing; a dashboard nobody trusts |
| **The card company** | Everything working except satisfaction; overrides; "write down why" |
| **The class readiness survey** | Reading a spider chart; spending on the weakest area |
| **Viacom** | An inward-facing need shown in falling revenue and profit; self-service; prediction; co-creation with four kinds of partner |
| **General Electric vs Siemens** | Scope, ways, means and ends: one failure, one success |
| **The retail ERP migration** | Nothing in it for the user; attitude versus ability |
| **The big-bang bank** | Building a data lake with no business use in mind |
| **Car maker and bank** | ITOT, PT, BT and DT side by side |
